# IP Guard

基于 **Next.js + shadcn/ui、Go、PostgreSQL、Redis** 的 IP 过滤配置管理系统。

目前实现管理员登录/退出、节点增删改查、网段增删改查、搜索和状态筛选。网段支持 IPv4/IPv6 CIDR、启停、ASN 和服务商信息。网段独立维护，节点测试和 CF 检测复用同一网段池，运行任务时选择对应网段。

已接入 mihomo v1.19.33 内核，用于批量筛选可用于代理节点的 IP。尚未实现规则下发或流量过滤，节点启用状态不表示在线状态。

## 筛选可用 IP

1. 在节点页选择「导入 VLESS 节点」，每行一条链接，支持 HTTPUpgrade、XHTTP、gRPC、WS 和 TCP。
2. 配置要测试的 IPv4/IPv6 网段。
3. 打开「连通性测试」，选择节点和网段，开始测试。系统逐个替换节点服务器地址为网段 IP，保留端口、UUID、SNI、Host 和传输参数。
4. 通过 mihomo 代理访问检测网址并返回延迟即视为可用，不额外限制 HTTP 状态码；可按延迟查看结果并复制可用 IP。连接失败或超时记为失败。

默认并发 5、单 IP 超时 5 秒；单次最多 4096 个去重 IP，覆盖所选网段全部地址，不做抽样。支持停止和刷新恢复，扫描轮次没有总时限，结果保存在 Redis 中 24 小时。这里测量连通延迟，不测下载带宽。

检测任务只解析和校验一次节点链接，各 IP 使用独立代理实例。工作协程按实际 IP 数量限制，结果采用有界缓冲和预分配内存。Redis 每秒检查停止请求并续租；进度变化时保存快照，无变化时每 10 秒更新心跳，结束时保存最终结果。

已有安装更新后执行 `npm run db:init`，保留已有配置并创建可用 IP 结果表。

## 可用 IP 列表

在「可用 IP」按协议与传输方式查看共用 IP 池，例如 `VLESS / XHTTP`、`VLESS / gRPC`、`VLESS / HTTPUpgrade` 各自独立。同池所有已启用节点均可直接生成节点链接，新增节点无需重新扫描。检测延迟来自最近一次成功检测的样本节点。支持 IP / ASN / 服务商搜索、协议筛选、分页和复制，页面每 10 秒刷新。

每轮结束后将各协议/IP 的最新状态保存到 PostgreSQL；复测失败仅移除对应池中的 IP，未检测地址保留原状态。停止时只保存已完成结果。修改、停用或删除样本节点不删除共用池；生成链接时使用当前启用节点的配置，保留认证、端口、SNI、Host 和传输参数。

列表通过 IPPure 基础信息接口异步查询当前页 IP 的归属地，展示国家或地区、国旗及省市信息。成功结果在 Redis 缓存 24 小时，失败缓存 1 分钟；查询失败显示「未知归属地」，不影响列表和节点链接。

## 华为云域名解析

支持将可用 IP 按 ISO 国家或地区代码发布到华为云公网 DNS，例如 `hk.reiiv.com`、`jp.reiiv.com`、`us.reiiv.com`；首次发现新地区会自动新增记录，IPv4 使用 A，IPv6 使用 AAAA。

1. 确保 `reiiv.com` 已在华为云公网 DNS 托管，注册商处的 NS 已指向该托管域名分配的服务器。
2. 在 Go API 环境变量配置 `HUAWEICLOUD_SDK_AK`、`HUAWEICLOUD_SDK_SK`，IAM 用户需要域名查询、记录查询/创建/修改/删除权限。区域默认 `cn-north-4`，可用 `HUAWEICLOUD_DNS_REGION` 修改；`HUAWEICLOUD_PROJECT_ID` 可选。密钥不会发送给浏览器。
3. 升级后执行 `npm run db:init` 创建 DNS 配置和历史表，重新构建并重启 Go API 与 Web 服务。
4. 打开「域名解析」，默认域名 `reiiv.com`、TTL 300 秒、每组最多 10 个 IP。选择协议池和探针，保存后点击「预览」检查，再「立即同步」或开启「定时同步」。定时同步默认关闭。

默认每 300 秒检查当前可用池中通过证书检查且未屏蔽的 IP。探针必须在线，在最近 5 分钟内有至少两次、跨度至少 60 秒的有效采样。最低采样成功率默认为 0，表示容忍偶发丢包：最新采样成功，或最近 60 秒内有新鲜成功采样且尚未连续失败满 60 秒，即可加入解析。连续失败至少 60 秒的 IP 会被排除，例如长期测不通的 `103.135.251.114`；采样中断不视为持续失败，过期数据也不会新增解析。所有达标 IP 按地区加入，默认每组最多 10 个，超出时优先选取平均延迟较低的 IP。若需要更严格的成功率门槛，可将最低采样成功率设为 1–100，此时还要求最新采样成功；已有策略保留保存的门槛，需要手动设为 0 才使用宽容规则。默认任一在线探针达标即可，也可以固定使用电信等指定探针；离线探针不作为失败证据。

系统接管各国家/地区缩写的全网默认 A / AAAA 记录（包括已有 `hk.reiiv.com`），保留其他线路及其他子域名。短暂丢包或采样不足的 IP 不会新增，已在解析中的待确认 IP 暂时保留；确认失败的 IP 仍会被移除。探针整体不可用或归属地无法完整确定时，本轮保留原解析。已接管的记录没有剩余合格或待确认 IP 时会删除；尚未接管且没有合格 IP 的记录保持原样。同名多条权重记录、CNAME 冲突或云端非正常状态会显示原因并跳过。停止定时同步保留已有解析。

任务在后台运行，页面展示云端/计划 IP、筛选原因、已提交操作及最近 10 次任务，数据库保留最近 100 次。同步前重新核对目标记录，发现期间发生的人工修改会跳过并等待下一轮；云端接口不支持条件更新，仍应避免同时手动修改同一记录。写入成功后需要等待云端处理及 DNS 缓存过期。预览不修改云端 DNS。

在 Go API 环境变量中设置 `FEISHU_DNS_WEBHOOK_URL` 为飞书自定义机器人的 Webhook 地址，重启 API 后启用 DNS IP 变动通知；留空关闭。手动和定时同步成功提交国家/地区二级域名的 IP 变更时，会发送蓝色标题卡片，按域名和 A / AAAA 类型分组，分别列出 🟢 新增 IP、🔴 移除 IP 及数量，并展示北京时间。新增解析列出全部新增 IP，删除解析列出全部移除 IP；预览、无变化和仅 TTL 变化不通知，大量变更自动拆分卡片。部分同步失败时仍通知已提交的变更；发送失败会在 DNS 任务及最近任务中显示警告，不回滚解析。本功能通知本系统同步提交的变更，不监控云端人工修改，也不自动重试未送达通知。Webhook 仅保存在服务器环境配置中，不返回浏览器。

## 本机延迟探针

打开「延迟探针」创建探针，填写显示名称（例如「电信」）、检测间隔、单 IP 超时、并发数和可选的出口网卡。部署密钥在服务器使用 AES-256-GCM 加密保存，刷新或重新登录后仍可直接复制原部署命令。只有手动重新生成密钥才会使旧密钥失效。探针在「可用 IP」页显示各探针最近的 ICMP 延迟，点击名称查看最近 1 小时到 7 天的历史曲线。结果保留 30 天。

已配置探针以列表展示，点击「编辑」配置系统和密钥，再在列表点击「一键部署」复制命令到被测电脑运行。直接下载预编译二进制，无需 Go、Node 或项目源码；也可在编辑弹窗直接下载 x64 / ARM64 程序。部署系统也会保存。旧版探针首次鉴权成功后自动补存原密钥，或在编辑中填写原密钥并保存，无需重新生成。

- macOS：安装到 `~/Library/Application Support/ip-list-probe`，通过 LaunchAgent 在登录后自动运行，日志位于该目录 `probe.log`。
- Linux：使用 sudo 安装到 `/opt/ip-list-probe`，注册 systemd 服务 `ip-list-probe`。需要 curl、系统 ping 和 systemd；日志 `journalctl -u ip-list-probe -f`。
- Windows：PowerShell 下载到 `%LOCALAPPDATA%\ip-list-probe`，使用当前用户的计划任务在登录后运行。

每台电脑安装一个探针，重复安装会更新该电脑的配置。配置文件只允许当前用户读取（Linux 为 root），密钥不放在后台进程参数或下载链接中。安装前会校验站点连接、密钥、系统 ping 和物理出口网卡，失败时保留原安装。手动运行支持 `-server`、`-token`、`-tls-pin` 或 `-config config.json`；`-check` 检查连接、鉴权和物理出口后退出。

服务器需配置固定的 `PROBE_CREDENTIAL_KEY`（用 `openssl rand -base64 32` 生成），与数据库分开保管并备份。更换或丢失此配置会使已保存的部署密钥无法解密；请勿随服务重启重新生成。升级后执行 `npm run db:init` 添加密文及系统配置列。

站点发布时先运行 `npm run probe:build`（服务器需要 Go），生成六个平台的静态二进制到 `bin/latency-probe`，再构建并重启 Web。下载入口 `/probe-downloads/` 只提供固定白名单中的公共安装文件，不包含探针密钥。自签证书站点在 Web 服务环境配置 `PROBE_TLS_PIN` 为 TLS 证书公钥的 SHA-256 base64 指纹，部署命令、下载和探针请求都会校验此公钥；证书公钥变更后需重新部署探针。公有 CA 证书可不设置，使用系统证书校验。

探针使用系统 `ping` 发 ICMP 包，测量电脑到目标 IP 的往返时间，不经过 HTTP/SOCKS 代理。探针会绑定物理网卡（macOS `ping -b`，Linux `ping -I`，Windows `ping -S` 绑定该网卡源地址）。网卡留空时自动选择唯一已连接且有 IP 的非隧道网卡；多个候选、无可用网卡或指定虚拟隧道时停止本轮检测并记录错误，不回退到默认路由。macOS 例如 `en0`，Linux 例如 `eth0`；Windows 的源地址绑定不能保证绕过所有第三方 VPN/TUN，请关闭 TUN 或为检测目标配置直连规则。日志会输出实际选择的网卡。探针需要能访问站点 HTTPS 地址；ICMP 超时可能是目标或网络屏蔽了 ICMP，不代表代理连接一定不可用。服务端使用 SHA-256 哈希验证 Bearer 密钥，并加密保存可恢复的部署密钥；只有已登录管理员可读取部署配置，列表及探针接口不返回密钥；上报只接受当前可用且未列入黑名单的 IP。数据库升级需执行 `npm run db:init`，再重启 Go API。

## 自动增量检测

新增已启用网段、修改 CIDR 或重新启用网段后，保存操作会自动为当前已配置的节点协议池和 CF 共用池加入增量检测队列，无需再选择网段或点击开始。没有有效已启用节点的协议池、没有检测域名的 CF 池不创建任务。

后台每 5 秒处理队列，空闲池自动开始；同池已有检测时排队，自动巡检在轮次间处理队列。队列持久化在 PostgreSQL，服务重启后继续处理。自动检测使用最近的检测参数，原样本不可用时改用同池其他已启用节点；没有历史配置时使用默认参数。节点的大网段会按每批最多 4096 个未检测 IP 自动分批完成。

系统从 PostgreSQL 的最新 IP 结果中排除已检测地址（包括成功和失败），仅检测新增或上次中断后未完成的 IP；重叠网段不重复检测，已有结果保留。节点按协议池独立判断，CF 按所有域名共用的池判断。仅修改名称、ASN 或备注不会重复触发；删除网段会移除待处理队列。手动停止自动任务会取消该网段在对应池的剩余自动检测。

「连通性测试」和「CF 优选」仍可手动选择「增量检测」或「全量检测」。修改检测域名、节点配置或需要复测失败地址时，请选择全量检测。自动检测记录与 CF 进度页会标明增量范围。正在进行的检测不会因为删除或停用网段而立即停止，可在检测页面手动停止。

升级后执行 `npm run db:init` 创建 `network_auto_scans` 队列表，再重启 Go API。API：`POST /scans` 和 `POST /cf-targets/{id}/scans` 支持 `incremental: true`；省略或设为 `false` 保持原有全量行为。手动节点增量请求的 `interval_minutes` 必须为 0。

## 自动巡检

在「连通性测试」选择样本节点与网段，默认间隔 5 分钟、每 12 轮全量扫描，点击「开始巡检」后由后台持续执行。不同协议池独立运行，可切换测试节点配置其他池，也可以选择单次检测。

页面按**检测记录**展示：每轮检测保存为一条记录，列出节点与协议池、轮次与范围、开始时间、可用 / 已测、可用率、耗时与状态；点开记录可查看该轮逐 IP 的结果、延迟与首次可用 / 恢复 / 失效变化，并可复制可用 IP。正在运行的一轮在列表中实时更新进度，巡检等待下一轮时顶部横幅显示下轮时间。记录保留最近 7 天，逐 IP 明细只为每池最近 30 轮保留，更早的记录仅保留汇总。

- 首轮扫描全部所选网段，日常轮次只复测可用 IP；第 13、25…轮重新全量扫描。全量频率为 1 时每轮扫描全部地址。
- 只有整段完整扫描且全部失败时，才在对应协议池中自动禁用网段。取消、中断或仅复测可用 IP 不触发整段禁用；其他协议和 CF 不受影响。
- 页面展示当前池禁用的空网段，可点击「恢复扫描」。后台后续轮次重新读取网段状态；修改 CIDR 后旧禁用状态失效。
- 升级初始化时，会一次性检查历史池：整段地址均有检测结果且无可用 IP 的，补齐对应协议池的禁用记录。手动恢复后再次初始化不会重新应用历史禁用；网段列表可查看并筛选「协议池已禁用」。
- 每池每轮结束后等待指定间隔，不重叠执行、不补跑积压轮次。同一协议池共用任务锁，不同池可独立巡检。
- 巡检配置和进度快照持久化到 PostgreSQL，离开页面继续运行，服务重启后自动恢复。原样本已删除或停用时，恢复过程选用同池其他已启用节点。显式停止会关闭该池的自动恢复。
- 页面显示轮次、范围、下轮时间及首次可用 / 恢复 / 失效变化。所有网段被禁用后等待恢复，仍可停止巡检。

`POST /scans` 的 `interval_minutes` 为 0 时单次检测，否则范围 1–1440；`full_every` 范围 1–288。`GET /scans/latest?protocol=vless%2Fxhttp` 获取对应池的最新任务，`GET /scan-records` 返回按轮次倒序的检测记录与仍在进行（或等待下一轮）的任务，`GET /scan-records/{id}` 返回单轮记录及该轮结果。`DELETE /protocol-networks/{id}?protocol=vless%2Fxhttp` 恢复该池中的网段。升级后运行 `npm run db:init`，创建共用池、协议网段状态、巡检配置与检测记录表，合并原有结果并保留最新状态。

## 本地启动

需要 Node.js 22+、Go 1.26+、Docker Compose；也可以直接使用已有 PostgreSQL 17+ 和 Redis 7+。

```sh
cp .env.example .env
# 编辑 .env：设置 ADMIN_PASSWORD，至少 12 个字符，不超过 72 字节
docker compose up -d --wait
npm ci
npm run db:init
```

分别在两个终端启动后端、前端：

```sh
npm run api:dev
```

```sh
npm run dev
```

访问 http://localhost:3000，使用 `.env` 的 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD` 登录。默认用户名为 `admin`，没有默认密码。重复执行初始化不会覆盖已有管理员密码。

Go 使用 godotenv 加载根目录 `.env`；Next.js 自动读取该文件。初始化后可从 `.env` 移除 `ADMIN_PASSWORD`，除非需要再次执行初始化。

## 结构和所用库

- `src/app`：Next.js 页面和服务端 API 代理。
- `src/components/ui`：shadcn/ui 原生组件，交互基于 Radix UI。
- `backend`：Go HTTP API，使用标准库路由。
- `backend/schema.sql`：管理员、节点、网段、可用 IP、延迟探针与结果等表。节点名称、手动节点地址端口、同一节点的 CIDR 均有唯一约束；探针结果保留 30 天。
- pgx：PostgreSQL 连接池和参数化查询。
- go-redis：Redis 连接；SCS + goredisstore：24 小时登录会话，登录时轮换令牌，退出时删除会话。
- ulule/limiter：Redis 登录限流，同一用户名每 15 分钟最多尝试 10 次，成功后重置。
- validator：通用字段校验；Go `net/netip`：CIDR 解析和网络边界校验。
- bcrypt：密码哈希。
- mihomo：使用现成的链接转换、代理传输和 URLTest；HTTPUpgrade 做兼容映射，不自行实现协议。

API 默认为 `127.0.0.1:8081`，浏览器通过 Next.js 服务端操作访问，Cookie 为 HttpOnly / SameSite=Lax。修改 `APP_ORIGIN` 时需要与前端访问来源一致。生产环境设置 `APP_ENV=production`、正确的 `APP_ORIGIN`，并通过 HTTPS 访问前端；后端保持仅内网可访问。Docker Compose 默认数据库密码仅用于本机开发。

## API

| ------------ | ---------------- | ------------------------ |
| POST         | `/auth/login`    | 用户名、密码登录         |
| POST         | `/auth/logout`   | 退出登录                 |

| GET / POST   | `/nodes`         | 节点列表 / 新增          |

### CF 优选

在「CF 优选」配置多个 HTTPS 检测域名（例如 `https://sub.bycn.de/`）。通过列表顶部「网段与检测配置」统一选择检测域名、已启用网段、超时与并发数，执行检测，结果汇入所有域名共用的 IP 池；新增域名直接复用现有 IP，无需重新检测，删除域名也不会删除共用 IP。

域名列表按表格展示可用 IP、上轮可用率、最后检测时间、添加时间，并提供「查看 IP」入口；添加域名在弹窗中完成。统一检测任务只有一个，进度单独放在「检测进度」页（`/cf/progress`），展示状态、进度、统计、配置摘要、本轮共用 IP 池与停止操作，启动检测后自动跳转到该页。域名详情页（`/cf/[id]`）只展示该域名自己的数据：可用 IP、上轮与累计可用率、检测轮次、最近 12 轮记录，以及该域名实际返回 2xx/3xx 的 IP 列表；共用池中由其他域名测出的 IP 不计入该域名列表。

该功能与代理节点检测独立，不需要 VLESS 节点模板；复用网段配置，不受 4096 IP 数量限制，重叠网段自动去重，按需生成待测地址，最多 32 并发，支持停止和刷新恢复进度。任务不设总运行时限，持续到全部地址检测完成或手动停止；单个 IP 仍按配置的请求超时执行。升级时执行 `npm run db:init`，原有各域名的结果按 IP 合并，采用最新检测状态。

进度页展示的任务按以下顺序确定：先取最近一次启动的检测；若它所属的域名已被删除，则回退到最近一次已完成检测（Redis 列表 `ipfilter:cf:done` 保留最近 5 条），仍无可用任务时显示空态。运行中的任务超过 50 秒没有心跳会标记为中断，避免服务重启后一直停在「检测中」。

检测使用 Go 标准库直接连接候选 IP，保留网址原始 Host、TLS SNI 和证书校验，不使用环境 HTTP 代理。HTTP 2xx / 3xx 计为可用，不跟随跳转；403、5xx、证书错误或超时均不计为可用。仅检测可用性，不额外判断 Cloudflare 响应头，不测量延迟或带宽。

每轮结束后，同一批结果写入三处：共用 IP 池（`cf_ip_pool`）、该域名的独立结果（`cf_results`）与轮次统计（`cf_target_rounds`），并更新 `cf_targets.last_checked_at`。因此域名详情既能列出「该域名返回的 IP」，也能按轮次给出可用率；旧数据没有轮次记录时，可用率回退为按域名结果计算。PostgreSQL 保留每个地址/IP 的最新检测结果；复测失败会移除可用记录，未检测或停止时尚未完成的 IP 保留旧结果。Redis 保存 24 小时的任务进度，服务中断需重新开始检测。升级后运行 `npm run db:init` 创建 `cf_targets`、`cf_results`、`cf_target_rounds` 表并回填 `last_checked_at`，再重启 Go API。

网段的 ASN 和服务商留空时会在保存时自动获取（RIPEstat 路由 ASN 与所属机构，Redis 缓存 24 小时），也可手动填写。查询失败不影响保存，并提示重试；修改 CIDR 会清除旧归属并重新查询。私有网段不查询，多 ASN 会完整展示；查询结果无法覆盖整个网段时不自动填充。服务启动时及每 30 分钟自动补全缺失的 ASN / 服务商，保留手动填写内容。升级需运行 `npm run db:init` 扩大 ASN 字段容量。归属信息会展示在代理可用 IP 和 CF 地址详情中；重叠网段优先采用有信息的最具体网段。可用 IP 列表可生成对应协议池中所有已启用节点的分享链接，保留认证、SNI 和传输参数，仅替换连接 IP。

相邻网段按各自 CIDR 独立保存，检测时只做重叠去重，不会把两个 `/23` 自动并成一个 `/22`；需要合并时先确认 SQL 里网段、协议池禁用行与历史记录三处都改到位，否则禁用状态会按 `(network_id, cidr)` 失配而失效。

升级运行后端 `-init` 会将旧网段迁移为独立配置，移除节点关联和访问策略；相同 CIDR 合并，保留备注和补充信息，任一副本启用则保留启用状态。若原任务选择了合并删除的网段，需重新选择。

本机启用 Clash 等 TUN 代理时，代理节点扫描可能经过已有代理，不能据此保证本地直连可用。可设置 `PROBE_INTERFACE=en0`（替换为实际物理网卡名）并重启 Go API，使用 mihomo 的网卡绑定功能指定检测出口；再重新扫描以更新旧结果。该配置不改变 CF 检测出口。

代理检测可设置 `PROBE_KERNEL=xray`，并通过 `XRAY_BIN` 指定已安装的 Xray 可执行文件（默认 `/usr/local/bin/xray`）。重启 Go API 后，正常扫描任务中的 HTTPUpgrade、XHTTP、gRPC、WS 和 TCP 请求将由 Xray 执行，停用 mihomo 检测路径；CF 检测保持原有直连方式。每个 IP 使用独立的 Xray 进程和私有 Unix socket，进程在检测结束、超时或取消时回收；超时包含进程启动时间，只有实际代理 HTTP 请求成功才记录可用。此方式会增加并发扫描的进程与内存开销，实际最多并行检测 8 个 IP，排队时间不占用单个 IP 的超时。设置 `PROBE_KERNEL=mihomo` 后重启可回退。现阶段保留 mihomo 的分享链接转换器以兼容已有配置。

## 入口证书校验

代理扫描先对候选 IP 的节点端口建立 3 次独立 TLS 连接，保留节点原始 SNI，严格验证域名、信任链和有效期，然后进行实际代理请求检测。每个 IP 的扫描超时覆盖整个校验过程。TLS 节点必须配置 SNI；明文节点保留原有代理连通性检测，不标记为证书已验证。

`/certificate-issues` 页面（同名受保护 GET API）显示证书异常的 IP、协议、SNI、实际证书和失败原因。相同 SNI 下存在未解决证书异常的 IP 不进入可用列表、节点生成或延迟探针目标。普通连接超时不作为证书错误；已有证书错误保留到重新校验成功。不同 SNI 的结果独立处理，手动黑名单保持独立。

升级后，历史未检查证书的可用结果暂不进入可用池，服务启动后会在后台对历史可用结果补做证书和代理请求检测；也可重新执行连通性检测。多次校验只能降低间歇性错误漏检概率，无法保证入口今后永远不变化。
